# 면담 A/B 평가

[English](README.md) · [한국어](README.ko.md)

같은 사용자 대화·모델·도구·판정 기준으로 **기본 에이전트**와 **스킬 적용 에이전트**를 비교합니다.
[DreambigOu/ELI5](https://github.com/DreambigOu/ELI5)의 평가 아이디어에서 출발해 독립적으로 작성했습니다.
출처는 [SOURCES.md](../SOURCES.md)에 기록했습니다.

**아직 성능 개선 수치를 주장하지 않습니다.** 오프라인 테스트는 실행 흐름, 파싱, 파일 근거, 채점 규칙을 검증합니다.
실제 유료 모델을 통한 Claude 어댑터 실행은 아직 검증하지 않았습니다.

## 모델 호출 없이 확인

Python 3.10 이상이 필요하며 평가기 자체는 표준 라이브러리만 사용합니다.

```sh
python3 scripts/run-evals.py
python3 scripts/run-evals.py --case jargon-probe --repeats 3 --seed 42
python3 -m unittest discover -s tests -v
```

`--live`가 없으면 케이스를 검증하고 실험 계획만 출력합니다.
Claude 실행, 외부 호출, 결과 파일 생성은 하지 않습니다.

## 실제 비교 실행

어댑터의 옵션을 지원하는 Claude Code와 환경변수로 설정된 API/프로바이더 인증이 필요합니다.
로컬 옵션은 2.1.118의 도움말로 확인했습니다. `--bare`는 구독 OAuth 로그인·키체인을 사용하지 않습니다.
[공식 안내](https://code.claude.com/docs/en/headless)를 참고하고,
계속 바뀌는 별칭 대신 사용하는 프로바이더가 지원하는 고정 모델 ID를 지정하세요.

```sh
python3 scripts/run-evals.py --live \
  --model YOUR_PINNED_MODEL_ID \
  --case jargon-probe --repeats 3 --seed 42 \
  --budget-usd 5 --timeout 180
```

채점을 포함해 **실제 비용이 발생**합니다. `--judge-model`로 채점 모델을 따로 고정할 수 있고,
생략하면 같은 모델을 씁니다. 보고된 비용을 누적해 남은 예산을 CLI의 호출별 예산으로 전달합니다.
프로바이더 차원의 결제 한도는 아닙니다. 실패·타임아웃 호출에는 보고되지 않은 비용이 생길 수 있습니다.
첫 실행·채점 오류 또는 예산 소진 후 중단하며, 부분 실행에는 비교 점수를 내지 않습니다.
추가 비용을 숨기는 자동 재시도·재개는 없습니다.

민감한 정보가 없는 폐기 가능한 환경에서 실행하세요. 임시 작업 폴더는 **OS 샌드박스가 아닙니다**.
면담에는 Read·Write·Edit·Glob·Grep만 허용하고 채점에는 도구를 주지 않습니다.
기본 스킬·슬래시 명령·자동 설정·MCP 서버 탐색을 끄고 호출마다 새 설정 폴더를 사용합니다.
환경변수의 프로바이더 설정이나 조직 정책은 여전히 영향을 줄 수 있으며 환경변수 자체는 로그에 남기지 않습니다.

## 비교 대상

[`evals.json`](evals.json)에 여섯 케이스가 있습니다.

| 케이스 | 확인할 행동 |
| --- | --- |
| vague-agent-spec | 모호함 구체화, 질문 수, 기록, 허위 준비 완료 방지 |
| jargon-probe | 쉬운 말로 흐름 설명, 모를 때 가르치기, 정확한 비유 |
| memory-tradeoff | 청중에 맞춘 설명과 중요한 결과의 오해 |
| informed-delegation | 이해한 위임·중단 요청 뒤 재시험하지 않기 |
| multi-audience | 원본과 독자별 문서 3종의 일치·정직성 |
| deferred-blocker | 차단 쟁점, incomplete 상태, 중단 존중 |

시스템 프롬프트와 사용자 입력은 양쪽에 동일합니다.
스킬 적용 쪽만 스킬 사본과 이를 읽으라는 지시를 받습니다.
케이스·반복·조건마다 저장소 밖에 새 작업 폴더를 만들고 기록한 시드로 실행 순서를 섞습니다.
기본 조건은 현재 작업 폴더를 통해 이 저장소의 스킬을 자동 발견하지 않습니다.
양쪽 모델 설정은 같지만 프로바이더의 비결정성까지 없애지는 못합니다.

방식은 **고정 사용자 답변을 이용한 대화 재생(scripted-turn replay)**입니다.
매 호출에 앞선 사용자·에이전트 응답을 전달하고 작업 파일은 이어집니다.
실제 사람이 적응해서 답하거나 네이티브 세션을 재개하는 실험은 아닙니다.
고정 후속 답변이 한쪽에 더 잘 맞을 수 있으니 대화 원문을 검토하고 실제 면담으로 보완해야 합니다.
이 Claude 어댑터로 Codex의 행동까지 검증한 것으로 표현하지 않습니다.

## 판정과 근거

- `file_exists`: 예상 경로에 비어 있지 않은 파일이 실제 존재하는가.
- `updates_after_reply`: 매 후속 답변 회차가 끝났을 때 마크다운 파일이 변경됐는가.
  이것만으로 다음 질문 **이전**에 썼다는 실행 순서까지 입증하지는 못합니다.
- `contract_consistency`: 원본과 3종 문서의 `source_revision`·`spec_status`가 같은가.
  원본 상태는 ready·incomplete·paused 중 하나입니다. 이는 메타데이터 검사이며 내용의 일치는 별도 채점합니다.
- `judge`: 모델이 pass·fail·unknown과 실제 응답·도구 이벤트·파일에서 인용한 근거를 반환합니다.
  누락·중복·잘못된 ID, 없는 인용, 형식 오류, 실행 실패가 있으면 비교를 확정하지 않습니다.

채점기에는 조건 이름 없이 사용자 대화와 근거를 주지만 말투로 스킬 여부를 알아챌 수 있습니다.
완전한 눈가림 실험은 아닙니다. 인용 검증은 문장이 존재함을 확인할 뿐 판정의 정답을 보장하지 않습니다.
결과를 사람이 검토해야 합니다.

기대한 모든 항목이 pass/fail로 판정되기 전에는 양쪽 통과율과 차이를 null로 남깁니다.
누락을 분모에서 빼지 않으며 판정 완료율(coverage)은 따로 제공합니다.
차이는 **이 케이스들의 항목 통과율 차이(%p)**입니다. 숨겨진 요구사항 발견률이나 시간 절약률이 아닙니다.
반복 실행 횟수만으로 통계적 신뢰구간을 주장하지 않습니다.

## 결과 파일

기본 경로는 Git에서 제외한 `evals/runs/<UTC timestamp>/`입니다.
`--output`으로 새 폴더를 지정할 수 있고 기존 경로는 덮어쓰지 않습니다.

```text
run.json                 # 시드, 실행 순서, 요청 모델, CLI 버전, 해시, 시각
cases.json               # 실제 선택한 케이스
skill-source/            # 고정한 스킬 원본
001-.../turn-1.jsonl      # CLI 이벤트; CLI가 제공하면 실제 모델 정보 포함
001-.../turn-1.json       # 회차 종료 시 응답과 파일 내용·해시
001-.../judge.jsonl       # 채점 원문
results.json             # 항목별 판정과 근거
summary.json             # 완료율, 통과율·차이 또는 incomplete, 보고된 비용
```

호출별 stderr도 보존합니다. 작업 폴더는 수집 후 제거합니다.
심볼릭 링크, UTF-8이 아닌 파일, 크기 제한을 넘은 출력은 조용히 제외하지 않고 오류로 처리합니다.
대화와 생성 파일에 민감한 맥락이 있을 수 있으니 로그는 검토 후 공유하세요.

## 케이스 추가

`evals.json`에 고정된 `turns`와 고유 ID의 `assertions`를 추가합니다.
관찰 가능하고 의사결정에 필요한 행동을 평가하세요. 이해한 위임, 설명 거부, 미결정 같은 반례도 포함합니다.
무례함이나 장황함을 보상하는 “매워야 한다” 항목은 넣지 않습니다.
CI는 오프라인 계획과 단위 테스트만 실행하며 유료 평가를 수행하지 않습니다.
